## 1. Executive Summary

In the **Phase 5.7 Audit Report ([FINDING-L01])**, telemetry inspection revealed that while Sentry SDK is configured with `send_default_pii=False` and a custom `before_send=sentry_scrub_event` hook (which redacts query-string OTP and PAN secrets for GSTR-1 EVC filing), **taxpayer identifiers (15-character GSTINs) continue to be captured in plain text** across:
1. HTTP route paths where GSTIN is a path parameter (e.g., `/api/vendors/scorecard/27AABCU9603R1ZM`, `/api/reconcile/history/27AABCU9603R1ZM`).
2. Query parameters on reconciliation and filing endpoints (e.g., `?supplier_gstin=27AABCU9603R1ZM`, `?gstin=...`).
3. Outgoing HTTP client breadcrumbs (`httpx`/`requests`) to external portals (Sandbox GST API, e-Invoice IRP, Tally Bridge).
4. Application log breadcrumbs generated by `_log.info` / `_log.warning` when logging GSTIN mismatches or fetch status.
5. Sentry performance transaction names and span descriptions.

Under Indian data protection and tax governance principles (DPDP Act & CBIC norms), a GSTIN directly embeds the 10-character Permanent Account Number (PAN) of the taxpayer in characters 3–12. Transmitting raw PANs to third-party telemetry aggregators constitutes unmasked PII exposure.

This audit establishes the **smallest safe masking boundary**:
- **What to mask**: Characters 3–12 (the embedded PAN) are redacted to `XXXXXXXXXX` (e.g., `27AABCU9603R1ZM` $\rightarrow$ `27XXXXXXXXXX1ZM`).
- **What to preserve**: The 2-digit State Code (characters 1–2, e.g., `27`) and the entity vertical/checksum suffix (characters 13–15, e.g., `1ZM`) are strictly preserved. This retains essential debugging context for Place of Supply (POS), inter-state vs. intra-state tax determinations, and multi-vertical registration identification without disclosing the taxpayer's legal identity.
- **Where to enforce**: Extend `app/filing/log_safety.py` with pure masking functions and wire them into Sentry's `before_breadcrumb` and `before_send_transaction` hooks in `app/main.py`.

### 2.2 Critical Gaps Identified
1. **`before_send_transaction` is Not Configured**:
   - Sentry traces 20% of requests (`traces_sample_rate=0.2`).
   - For parameterized routes or raw path fallbacks, `transaction` names, HTTP request URLs, and child span descriptions are sent to Sentry without passing through `before_send`.
2. **`before_breadcrumb` is Not Configured**:
   - Breadcrumbs recorded prior to an exception (HTTP client calls to external APIs, SQL queries, and log records) are collected unscrubbed.
3. **`sentry_scrub_event` is Restricted to Query Keys**:
   - In `app/filing/log_safety.py`, `sentry_scrub_event` only inspects `request.query_string` and query parts of `request.url` for `SENSITIVE_QUERY_KEYS` (`otp`, `pan`, `signature`, etc.).
   - It does **not** inspect or mask URL path segments, transaction names, or breadcrumb messages.

## 4. Statutory & PII Masking Specification

### 4.1 GSTIN 15-Character Anatomy
Under Section 22 of the CGST Act, 2017, a Goods and Services Tax Identification Number (GSTIN) is structured as:

$$\underbrace{\text{27}}_{\substack{\text{State Code} \\ \text{(Chars 1--2)}}} \quad \underbrace{\text{AABCU9603R}}_{\substack{\text{Taxpayer PAN (PII)} \\ \text{(Chars 3--12)}}} \quad \underbrace{\text{1}}_{\substack{\text{Entity} \\ \text{Code}}} \quad \underbrace{\text{Z}}_{\substack{\text{Default} \\ \text{Char}}} \quad \underbrace{\text{M}}_{\substack{\text{Check} \\ \text{Digit}}}$$

- **Chars 1–2 (State Code)**: Numeric `01`–`38`, `97`, `99`. Indicates the tax jurisdiction. Essential for tax calculation and POS logic.
- **Chars 3–12 (PAN)**: 5 uppercase alphabets + 4 numeric digits + 1 uppercase alphabet (`[A-Z]{5}[0-9]{4}[A-Z]`). **Direct Taxpayer Identifier (PII)**.
- **Chars 13–15 (Suffix)**: 1 alphanumeric entity vertical code + uppercase `Z` + 1 alphanumeric checksum digit (`[1-9A-Z]Z[0-9A-Z]`).

### 4.2 Masking Format Specification
- **Masking Pattern**: Replace the 10-character PAN segment (chars 3–12) with `XXXXXXXXXX` (or 10 asterisks / Xs).
- **Transformation Example**:
  $$\text{27AABCU9603R1ZM} \longrightarrow \mathbf{\text{27XXXXXXXXXX1ZM}}$$
  $$\text{07AAAAA0000A1Z5} \longrightarrow \mathbf{\text{07XXXXXXXXXX1Z5}}$$
- **Preservation Invariant**:
  - `len(masked_gstin) == 15` (identical string length; preserves fixed-width formatting and layout).
  - State code preserved $\rightarrow$ Sentry error reports still indicate whether a failure was specific to Maharashtra (`27`), Delhi (`07`), or Karnataka (`29`).
  - Suffix preserved $\rightarrow$ Multi-branch entities (`1Z...` vs `2Z...`) remain distinguishable in logs.
  - Taxpayer PAN obscured $\rightarrow$ Zero legal entity or proprietor PAN disclosure.

### 4.3 Collision & False-Positive Analysis
To prevent accidental mutation of non-GSTIN values, the matching regex must enforce strict negative lookbehind and lookahead boundaries:

```python
_GSTIN_MASK_REGEX = re.compile(
    r"(?<![A-Za-z0-9])([0-9]{2})([A-Za-z]{5}[0-9]{4}[A-Za-z])([1-9A-Za-z]Z[0-9A-Za-z])(?![A-Za-z0-9])"
)
```

**Verification against potential collision targets**:
1. **UUIDs** (`3e01d320-0fb8-4898-ae38-1d8fc7849e47`):
   - Components are lengths 8, 4, 4, 4, 12. No 15-character sequence matches the pattern. **Safe (No match)**.
2. **SHA-256 Hashes** (`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`):
   - 64 continuous alphanumeric characters. Negative lookbehind and lookahead reject sub-matches. **Safe (No match)**.
3. **Invoice Numbers** (`INV-2026-001`, `VCH-000452`, `BILL/2026/99`):
   - Do not conform to `\d{2}[A-Z]{5}\d{4}[A-Z]...`. **Safe (No match)**.
4. **Timestamps & Dates** (`2026-09-22T16:04:45.507215+00:00`, `2026-03`):
   - Separated by hyphens/colons. **Safe (No match)**.
5. **Integer Paise Amounts** (`100000`, `5000000`):
   - Pure numeric digits without alphabet characters. **Safe (No match)**.

## 5. Smallest Safe Masking Boundary & Architectural Design

### 5.1 Location of Logic: `app/filing/log_safety.py`
The log safety module [`app/filing/log_safety.py`](file:///Users/omkarkadam/Documents/ReconDesk/recondesk-backend/app/filing/log_safety.py) is already the designated central repository for Sentry scrubbing and sanitized HTTP formatting.

The planned functions to add to `log_safety.py`:
1. `mask_gstin(text: str) -> str`:
   - Pure string transformer. Replaces all valid GSTIN substrings with their masked equivalent.
2. `scrub_data_recursively(obj: Any) -> Any`:
   - Walks dictionaries, lists, and primitives, applying `mask_gstin` and `scrub_url` to strings.
3. `sentry_scrub_breadcrumb(crumb: dict[str, Any], hint: Optional[dict[str, Any]] = None) -> dict[str, Any]`:
   - Sentry `before_breadcrumb` callback. Masks `crumb["message"]` and all fields in `crumb["data"]` (e.g. `url`, `query`, `description`).
4. `sentry_scrub_transaction(event: MutableMapping[str, Any], hint: Optional[dict[str, Any]] = None) -> MutableMapping[str, Any]`:
   - Sentry `before_send_transaction` callback. Masks `event["transaction"]`, `event["request"]["url"]`, `event["request"]["query_string"]`, and child spans.
5. Enhance existing `sentry_scrub_event(event: MutableMapping[str, Any], hint: Optional[dict[str, Any]] = None) -> MutableMapping[str, Any]`:
   - Extend existing `before_send` handler so error events also mask GSTINs in `request["url"]`, `request["query_string"]`, `transaction`, and `exception["values"]`.

### 5.2 Hook Registration in `app/main.py`
In `app/main.py`:
```python
if settings.SENTRY_DSN:
    from app.filing.log_safety import (
        sentry_scrub_breadcrumb,
        sentry_scrub_event,
        sentry_scrub_transaction,
    )

    sentry_sdk.init(
        dsn=settings.SENTRY_DSN,
        environment=settings.APP_ENV,
        integrations=[
            StarletteIntegration(transaction_style="endpoint"),
            FastApiIntegration(transaction_style="endpoint"),
        ],
        traces_sample_rate=0.2,
        profiles_sample_rate=0.1,
        send_default_pii=False,
        before_send=sentry_scrub_event,
        before_send_transaction=sentry_scrub_transaction,
        before_breadcrumb=sentry_scrub_breadcrumb,
    )
```

### 5.3 Performance & Reliability Impact
- **CPU Overhead**: Zero network calls; regex evaluation on small strings (URLs and breadcrumb metadata) takes $< 0.05\,\text{ms}$.
- **Fail-Safe Contract**: If `mask_gstin` encounters non-string or malformed inputs, it returns the input unmodified without raising exceptions.
- **Zero Impact when `SENTRY_DSN` is Unset**: In environments without Sentry configured (e.g. standard local test runs), the entire block remains inactive.
