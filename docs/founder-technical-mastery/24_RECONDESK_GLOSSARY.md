## 1. Indian GST Compliance & Statutory Tax Lexicon

* **Input Tax Credit (ITC)**: The tax paid by a registered business on purchases of goods or services used in the course of business, which can be legally deducted from the tax payable on outward sales.
* **GSTR-1**: The statutory monthly or quarterly return of outward supplies (sales invoices, credit notes, export invoices) filed by a supplier on the GST portal.
* **GSTR-2A**: A dynamic, read-only view of inward supplies auto-drafted from suppliers' GSTR-1 filings, updated continuously in real time as suppliers file.
* **GSTR-2B**: A static, auto-drafted monthly ITC statement generated by the GSTN on the 14th of every month. It serves as the official legal baseline determining which purchases are eligible for ITC in the current month's GSTR-3B.
* **GSTR-3B**: The mandatory monthly self-assessed summary return where taxpayers declare their outward tax liabilities, claim ITC, reverse ineligible credits, and pay net tax.
* **GSTR-9 / GSTR-9C**: GSTR-9 is the consolidated annual return; GSTR-9C is the reconciliation statement certified by a Chartered Accountant for businesses with aggregate turnover exceeding ₹5 Crore.
* **Invoice Management System (IMS)**: A government mechanism introduced in October 2024 allowing buyers to Accept, Reject, or mark invoices as Pending before GSTR-2B is finalized.
* **Reverse Charge Mechanism (RCM)**: A statutory scenario where the liability to pay GST to the Government shifts from the supplier to the buyer (recipient). The buyer must pay tax in cash before claiming it as ITC.
* **Section 16(2)(c)**: The provision of the CGST Act stipulating that a buyer can claim ITC only if the supplier has actually paid the tax to the Government.
* **Section 17(5)**: The "Blocked Credit" provision specifying purchases on which ITC is statutorily prohibited (e.g., motor vehicles, outdoor catering, employee club memberships).
* **Rule 37**: The statutory rule mandating that if a buyer fails to pay a supplier within 180 days of the invoice date, the claimed ITC must be reversed in GSTR-3B with 18% annual interest.
* **Rule 88C (Form DRC-01B)**: Automated system notice issued when tax liability declared in GSTR-1 exceeds the liability paid in GSTR-3B by more than 10% or ₹25,000.
* **Rule 88D (Form DRC-01C)**: Automated system notice issued when ITC claimed in GSTR-3B exceeds the ITC available in GSTR-2B.
* **HSN / SAC Code**: Harmonized System of Nomenclature (for goods) and Services Accounting Code (for services), standardized numerical codes used to classify products for GST rates.
* **Place of Supply (POS)**: The statutory location determining whether a supply is subject to intra-state tax (CGST + SGST) or inter-state tax (IGST).

## 2. Software Architecture & Database Engineering

* **ACID Guarantees**: Four key database transaction properties: Atomicity (all or nothing), Consistency (preserves schema constraints), Isolation (concurrent transactions do not interfere), and Durability (committed changes persist).
* **AWS Aurora Serverless v2**: An on-demand, auto-scaling relational database engine compatible with PostgreSQL that scales compute capacity in fractional Aurora Capacity Units (ACUs) within milliseconds.
* **Aurora Capacity Unit (ACU)**: The unit of compute and memory capacity in Aurora Serverless (1 ACU $\approx$ 2 GB of RAM, plus corresponding CPU and networking).
* **Connection Pooling**: A cache of database connections kept open so that incoming requests can borrow and return existing connections in microseconds, avoiding expensive TCP handshakes.
* **SQLAlchemy**: The premier Python Object Relational Mapper (ORM) and SQL toolkit providing connection pooling, statement compilation, and declarative models.
* **Alembic**: A lightweight database migration tool for Python, generating sequential versioned scripts to evolve database schemas safely without downtime.
* **PostgREST-to-SQL Adapter (`AuroraClient`)**: ReconDesk’s custom database client that translates fluent PostgREST method calls (`.table().select().eq().execute()`) into parameterized SQL executed directly on AWS Aurora via SQLAlchemy.
* **Integer-Paise Financial Math**: The practice of storing all monetary figures as integers in paise (1 INR = 100 Paise) using 64-bit BigInteger columns, completely eliminating IEEE 754 floating-point rounding errors.
* **Multi-Tenancy Isolation**: Architectural pattern ensuring that multiple customer accounts (firms) share the same underlying database infrastructure while maintaining strict, mathematically enforced isolation between their data.

## 3. Distributed Systems, Queues & DevOps

* **ASGI (Asynchronous Server Gateway Interface)**: The modern Python standard for asynchronous web servers (e.g. Uvicorn) allowing non-blocking network I/O and concurrent request handling.
* **Event Loop**: A continuous programming loop in `asyncio` that checks for pending tasks, executes them, and pauses them when awaiting network or disk I/O, allowing a single thread to handle thousands of concurrent connections.
* **Celery**: An asynchronous distributed task queue system for executing heavy background jobs outside the HTTP request-response cycle.
* **Redis Broker**: An in-memory key-value data store used by Celery to queue job payloads and transport messages between the web server and background workers.
* **Late Acknowledgement (`task_acks_late=True`)**: A Celery configuration where a worker acknowledges task completion to Redis only after finishing execution. If the worker crashes mid-task, the job is not lost.
* **Heartbeat Watchdog**: A background supervisor process that monitors worker liveness. If a worker fails to emit a heartbeat for >900 seconds, the supervisor marks the job as `FAILED` and raises alerts.
* **Dead Letter Queue (DLQ)**: A dedicated failure queue where unrecoverable, repeatedly failing tasks are archived for forensic engineering analysis.
* **Caddy 2**: A modern, high-performance HTTP/2 reverse proxy written in Go that automatically provisions and renews TLS certificates via Let's Encrypt.
* **HSTS (HTTP Strict Transport Security)**: A web security header informing browsers that the application must only be accessed over encrypted HTTPS connections.
* **Cloudflare R2**: An S3-compatible, zero-egress-fee distributed object storage service used by ReconDesk for raw uploads and large reconciliation result payloads.

## 4. Algorithms, Data Structures & Cryptography

* **Levenshtein Distance**: The minimum number of single-character insertions, deletions, or substitutions required to transform one string into another.
* **RapidFuzz**: A high-performance, C++-accelerated library that computes string distance metrics using SIMD CPU vectorization.
* **OCR Character Transliteration**: Mapping optical confusion glyph pairs (e.g. `O` $\leftrightarrow$ `0`, `I` $\leftrightarrow$ `1`, `S` $\leftrightarrow$ `5`) into canonical representations before comparison.
* **Dynamic Programming Sequence Alignment**: An algorithmic technique (Needleman-Wunsch variant) that finds the optimal alignment between two invoice strings under zero-padding and OCR substitution costs.
* **Candidate Blocking**: Partitioning a large dataset into indexed hash buckets (by normalized invoice, OCR string, or tax amount) to avoid the $O(N \times M)$ cartesian product during search.
* **JSON Web Token (JWT)**: An open standard (RFC 7519) defining a compact, self-contained method for securely transmitting authenticated user identity claims as a digitally signed JSON object.
* **JWKS (JSON Web Key Set)**: A set of cryptographic public keys published by an identity provider (like Amazon Cognito) used by resource servers to verify RS256 asymmetric signatures without sharing private secrets.
* **RS256**: An asymmetric cryptographic algorithm that signs tokens using an RSA private key and verifies them using a public key.
* **HMAC-SHA256**: A keyed-hash message authentication code used by Razorpay to verify that incoming webhook payloads originate authentically from Razorpay and were not tampered with in transit.
* **IDOR (Insecure Direct Object Reference)**: A security vulnerability where an application exposes a reference to an internal object (such as a database record ID) without validating whether the current user has permission to access it. ReconDesk prevents IDOR by enforcing `firm_owner_id` scoping on every query.
