## 1. Executive Summary & Curriculum Philosophy

True technical mastery is not achieved by memorizing syntax or skimming documentation; it is developed through **structured, first-principles study connected directly to real-world production code.**

As an AI-native founder, you have already accomplished what takes traditional engineering teams years: you have designed, built, tested, and deployed an enterprise SaaS platform processing statutory financial data. Your objective now is to **solidify the foundational computer science, distributed systems theory, and database mechanics** that underpin your software.

This curriculum is structured into **six progressive, self-paced phases**:
1. **Phase 1**: Python 3.11 Runtime, CPython Internals & Asynchronous I/O
2. **Phase 2**: High-Performance Web Protocols, FastAPI & Edge Infrastructure
3. **Phase 3**: Relational Database Engineering, PostgreSQL Internals & ACID Transactions
4. **Phase 4**: Distributed Systems, Celery Task Queues & Redis Architectures
5. **Phase 5**: Algorithmic Complexity, SIMD String Vectorization & Inverted Indexing
6. **Phase 6**: Enterprise Application Security, Multi-Tenancy & Site Reliability (SRE)

Every phase includes:
- **Theoretical Foundations**: The core computer science concepts.
- **Hands-On Codebase Labs**: Concrete exercises exploring ReconDesk's real source files.
- **Authoritative Reading Material**: The foundational textbooks, RFCs, and engineering papers.
- **Mastery Verification Gate**: Self-assessment questions you must be able to answer fluently before advancing.

## 2. Phase 1: Python 3.11 Runtime, CPython Internals & Asynchronous I/O

### Theoretical Foundations
- **CPython Virtual Machine**: Source code $\rightarrow$ AST $\rightarrow$ Bytecode (`.pyc`) $\rightarrow$ Evaluation loop (`ceval.c`).
- **Memory Management & Pymalloc**: Arenas, pools, blocks, small-object allocator, and cyclic garbage collection (generations 0, 1, 2).
- **The Global Interpreter Lock (GIL)**: Why multithreading in CPython does not utilize multiple CPU cores for CPU-bound tasks, and why multiprocessing (or C-extension SIMD) is required.
- **The Asynchronous Event Loop**: Cooperative multitasking, coroutines (`async`/`await`), tasks, futures, and epoll/kqueue selectors.

### Hands-On Codebase Labs in ReconDesk
1. **Lab 1.1: Bytecode Disassembly**:
   Inspect the bytecode generated by integer paise addition vs float addition:
   ```bash
   python -c "import dis; dis.dis('a = 1000 + 2000')"
   python -c "import dis; dis.dis('a = 10.0 + 20.0')"
   ```
2. **Lab 1.2: Event Loop Inspection**:
   Open [`recondesk-backend/app/main.py:207-241`](file:///Users/omkarkadam/Documents/ReconDesk/recondesk-backend/app/main.py#L207-L241) and trace how `stuck_job_detector()` executes `asyncio.sleep(300)` and offloads synchronous tasks to worker threads via `asyncio.to_thread(_stuck_job_tick)`.

### Recommended Reading

- PEP 492: Coroutines with async and await syntax.
- RealPython Guide to CPython Internals by Anthony Shaw.

## 3. Phase 2: High-Performance Web Protocols, FastAPI & Edge Infrastructure

### Theoretical Foundations
- **ASGI vs WSGI**: Why traditional WSGI (Django/Flask) allocates one thread per request, and how ASGI multiplexes thousands of concurrent connections over non-blocking event loops.
- **Pydantic v2 Compiled Core**: How Pydantic v2 uses `pydantic-core` (written in Rust) to validate JSON schemas directly in native machine code without Python interpreter overhead.
- **HTTP/2 & HTTP/3 Transport**: Multiplexing, stream prioritization, header compression (HPACK/QPACK), and how QUIC (UDP) eliminates TCP head-of-line blocking.
- **TLS Handshake & Automated PKI**: Asymmetric RSA/ECDSA key exchange, certificate authority chains, and the ACME protocol for automated Let's Encrypt certificate issuance in Caddy 2.

## 4. Phase 3: Relational Database Engineering, PostgreSQL Internals & ACID Transactions

### Theoretical Foundations
- **ACID Guarantees**: Atomicity, Consistency, Isolation (Read Committed, Repeatable Read, Serializable), and Durability (Write-Ahead Logging).
- **PostgreSQL MVCC (Multi-Version Concurrency Control)**: How rows are never overwritten in place (`xmin`, `xmax`, dead tuples, and table bloat).
- **Indexing Data Structures**: B-Trees, Hash indexes, GIN indexes, and why unindexed foreign keys cause table locks during cascading deletions.
- **Connection Pooling & Lock Contention**: QueuePool semantics, row-level locks (`SELECT FOR UPDATE`), and table-level lock escalation.

## 6. Phase 5: Algorithmic Complexity, SIMD String Vectorization & Inverted Indexing

### Theoretical Foundations
- **Asymptotic Complexity**: Big-O ($O$), Big-Omega ($\Omega$), and Big-Theta ($\Theta$) notation; worst-case vs average-case analysis.
- **String Distance Metrics**: Levenshtein edit distance, Damerau-Levenshtein, Jaro-Winkler, and dynamic programming Wagner-Fischer algorithm ($O(N \times M)$).
- **SIMD (Single Instruction, Multiple Data)**: How modern x86-64 CPUs (AVX2, AVX-512) execute 8 to 16 character comparisons in a single CPU cycle.
- **Candidate Blocking & Inverted Indexing**: Transforming combinatorial search spaces into constant-time hash lookups.
